# 3라운드 점검·최적화·간결화 — 설계

- 날짜: 2026-09-30
- 목적: 서비스 점검 — 버그·오류·불필요 실행 제거, UI/UX 간결화
- 이전: 1라운드 첫인상(`2026-09-28-visual-overhaul-design.md`), 2라운드 기술 깊이(`2026-09-29-round2-tech-depth-design.md`)
- 사용자 결정: 진행 방식 A(점검 먼저 → 발견 목록 승인 → 묶음 수정), 범위 전 화면, 삭제 허용(후보는 승인 후), 성공 기준 체감 위주·문서 최소

## 1. 1단계 — 전수 점검 (읽기 전용)

| 점검 | 대상 | 방법 |
|---|---|---|
| 백엔드 | api·worker 오류 경로, 불필요 쿼리·N+1·중복 조회, 쓸모없는 폴링·스레드·스케줄러, 안 쓰는 엔드포인트·죽은 코드 | 코드 읽기, 컨테이너 로그 WARN/ERROR, 엔드포인트 ↔ 웹 호출처 대조 |
| 웹 런타임 | 화면별 콘솔 오류·경고, 유휴 요청·타이머·렌더 루프, 메모리 증가, 안 쓰는 번들 코드 | 헤드리스로 홈·뷰어(소형·초대형)·모니터·FM·지도·키오스크 순회, 화면당 유휴 60초 계측 |
| UI 목록 | 화면별 컨트롤 전부(버튼·토글·패널·단축키), 중복 경로, 쓸 일 없는 요소, 과밀 영역 | 화면별 스크린샷·컨트롤 목록·같은 일을 하는 경로 대조 |

- 결과: 발견 목록 한 장 — 항목마다 번호(B 버그·P 불필요 실행·U UI), 근거(파일:줄·스크린샷), 추천 조치(고침·삭제·접기·그대로) 미리 채움
- 승인: 사용자는 추천과 다른 항목만 지정 — 라운드 유일한 정지 지점
- 데이터 손실·보안 문제는 목록을 기다리지 않고 즉시 보고

## 2. 2단계 — 묶음 실행

| 순서 | 묶음 | 내용 |
|---|---|---|
| R3-1 | 삭제·간결화 | 승인된 기능 삭제 + 딸린 API·코드·테스트 정리, 접기·재배치 — 지울 코드의 버그를 고치는 헛수고 방지 |
| R3-2 | 버그·오류 | 콘솔 오류·예외 경로·경쟁 상태·잘못된 표시 — 구조 확정 뒤 |
| R3-3 | 불필요 실행 제거 | 유휴 렌더·타이머·폴링, 중복 조회, 과한 재조회, 번들 정리 |

- 예외: 데이터 손실·보안·크래시급 버그는 R3-1 보다 먼저
- 방식: 묶음마다 브랜치 → 서브에이전트 구현·태스크 리뷰 → 최종 리뷰 → main 병합. 목록 승인 뒤 무중단, 세부 판단은 원장 판정
- 계획: 점검 결과 목록이 요구사항 — R3 전체 계획 하나(태스크 = 묶음 안 작업 단위)
- 삭제 경계
  - 기존 Flyway 마이그레이션 수정 금지 — 컬럼·테이블 삭제는 새 마이그레이션
  - 샘플 데이터·생성기(`gen_mep.py`)·공개 데모 모드는 유지
  - README 기능 설명·스크린샷과 어긋나면 같은 묶음에서 함께 정리

## 3. 검증·문서

- 태스크마다 기존 테스트(api·web·worker·load) 통과, 새 테스트는 고친 버그 재발 방지만
- 묶음마다 헤드리스 전 화면 순회 — 콘솔 오류 0·페이지 오류 0, 전후 스크린샷
- 최종 보고: 화면별 전후 스크린샷 몇 장 + 체감 요약. 수치 표 없음
- README: 바뀐 화면 재촬영·삭제 기능 설명 제거·"현재 범위와 다음 단계" 갱신만. `docs/screen-design.md` 는 삭제된 요소·API 만 반영

## 4. 환경·규칙

- 배포: api jar 교체, worker 이미지 교체, web 컨테이너 빌드(사내망 TLS 가로채기 — 컨테이너 안 gradle·pip 불가)
- 커밋 금지: `docs/learning/`, `docs/superpowers/specs/2026-09-07-virtual-building-expansion-review.md`
- 문서 문체: 불릿 + 명사형 짧은 구
- 푸시: 전 묶음 완료 뒤 사용자 확인 → Gun-stack 토큰
