순서: **① 가상 건물 확장(이 문서)** → ② 3D Tiles(워커 타일러·뷰어 로더·meshopt 압축) → ③ COBie xlsx → ④ GIF 재녹화·README 규모 측정.

## 목표

`samples/gen/gen_mep.py`(현재 지하 2층 + 지상 3층 + 옥탑, 36×16 m, 14계통 474요소)를 인자로 층수·부속동·말단 밀도를 바꿀 수 있게 확장한다.
기본값은 중형(약 3천 요소), 대형 인자(약 1만 5천 요소)는 ②의 타일링 검증과 README 규모 측정에 쓴다.
계통·연결 규약(IfcRelConnectsElements Relating=상류)과 Pset_BimStatus 는 그대로 유지한다. 변환기·API 는 변경하지 않는다. 화면은 층 단면 링크 한 곳만 고친다(§7).

## 1. 인자

```
python gen_mep.py [out.ifc] --floors 10 --annex 1 --density mid
```

| 인자 | 기본 | 의미 |
|---|---|---|
| `out.ifc` | `mep-building.ifc` | 출력 경로 (기존 위치 인자 유지) |
| `--floors N` | 10 | 지상 층수, **3 이상**(2F 에스컬레이터 개구부·3F 덤웨이터 개구부가 고정). 지하 2층(B2·B1)·옥탑(RF)은 고정 |
| `--annex K` | 1 | 부속동 수 0~2. 1=주차타워(지상 3층), 2=주차타워+후생동(지상 2층) |
| `--density` | `mid` | `low`(현재 수준·격자 없음) / `mid`(격자 4 m) / `high`(격자 2.5 m + 콘센트) |

범위를 벗어난 값은 argparse 오류로 종료. 대형: `--floors 20 --annex 2 --density high`.

## 2. 층 표고·층고

한 함수 `floor_spec(n_floors)` 가 `[(이름, 표고 z, 층고 h, 유형)]` 을 돌려준다.

| 층 | 표고 | 층고 | 유형 |
|---|---|---|---|
| B2, B1 | −7.0, −3.5 | 3.5 | 지하(현행 그대로 — 램프 rise·길이·개구부 계산에 3.5 가 박혀 있어 바꾸지 않는다) |
| 1F | 0.0 | 5.0 | `lobby` |
| 2F | 5.0 | 3.5 | `dining` |
| 3F~NF | 누적 | 3.5 | `office` |
| RF | NF 상단 | 3.0 | 옥탑(현행 코드) |

현재 전역 상수 `H` 를 쓰는 지상층 코드(외벽·샤프트 벽·공간 높이·천장 말단 z·계단 rise)는 해당 층의 `h` 를 받는다. 계단은 `ramp(run=2.0, rise=h/2)` 두 단. 높이 상수 두 개를 구분한다:

- `RF` = 옥상 슬래브 상단 = 최상 지상층 `z + h`. 입상관·트레이·덕트·엘리베이터의 `top` 은 이 값(현행 `top` 과 같은 의미).
- `RF_TOP` = `RF + 3.0` 옥탑 상단. 현행 `RF - top + 1.2` 같은 식은 `RF` 기준을 유지해 음수 높이가 나오지 않게 한다.

## 3. 지상층 평면 유형과 말단 격자

### 평면 사양(한 곳)

```python
PLAN = {
  "lobby":  [("로비", 0, 0, 13, D), ("상가1", 20.6, 0, 7.7, D), ("상가2", 28.3, 0, W-28.3, D)],
  "dining": [("식당", 0, 0, 13, D), ("회의1", 20.6, 0, 7.7, D), ("회의2", 28.3, 0, W-28.3, D)],
  "office": [("사무A", 0, 0, 13, D), ("사무B", 20.6, 0, W-20.6, D)],
}
```

코어(x 13~20.6)는 현행 샤프트·엘리베이터·계단실 좌표 그대로. 각 실은 IfcSpace `"{층}-{실}"` 로 생성되고, 설비 배치도 같은 목록을 읽는다(현재 118~120행과 334행에 갈라진 하드코딩을 통합).

### 말단 배치 `fit_zone(sp, x, y, w, d, z, h, ctx)`

실 사각형 안에 격자로 말단을 놓는다. `ctx` 는 그 층의 상류 객체 묶음(아래 표의 연결 대상 전부: 구역 분전반의 상류 트레이, 조명제어반, 비상분전반, 층 중계기, 알람밸브, 급수·급탕·배수·냉온수 분기관, 풍량댐퍼, DDC). 본동 지상층은 현행 층 루프가 채우고, 후생동은 §4 의 자체 공급원으로 채운다(없는 항목은 `None` 이면 해당 말단을 만들지 않는다).

격자 규칙:
- 실 경계 안쪽 여유 0.8 m. 격자 원점은 `(x + 0.8, y + 0.8)`, x 먼저 증가 후 y 증가(인덱스 순서 고정).
- 제외 영역: `SHAFTS`(EPS·PS·DS·EV·ST1·ST2) 사각형을 0.3 m 확장한 것과 에스컬레이터·덤웨이터 개구부 사각형. 안에 떨어지는 격자점은 버린다. ST1(x 10.4~13, y 10~14.6)이 사무A 안에 있으므로 코어 x 범위만 피해서는 부족하다.
- 감지기 인덱스 0 은 항상 존재(원점 격자점은 제외 영역 밖). 데모 상태 키는 인덱스 0 과 마지막 인덱스만 쓴다.

| 말단 | 배치 | 계통 연결(현행 규칙 유지) |
|---|---|---|
| 조명 | 격자 피치 P(mid 4 / high 2.5), 천장 h−0.35 | 구역 분전반 → 조명, 조명제어반 → 조명 |
| 스프링클러 | 격자 피치 P, 오프셋 P/2 | 알람밸브 → 층 주관 → 헤드 |
| 디퓨저 | 격자 피치 2P | VAV → 구역 덕트 → 디퓨저 |
| 연기·열감지기 | 격자 피치 2P (모서리 1개는 열감지기) | 감지기 → 층 중계기 |
| 콘센트(IfcOutlet POWEROUTLET) | `high` 만. 벽면 따라 3 m 간격 | 구역 분전반 → 콘센트 |
| ~~스위치~~ | 넣지 않음 — 전원 API 가 `IfcSwitchingDevice` 전부를 ATS 로 취급(StatusService.power/powerSource) | |
| 비상조명 2, 소화전 1, 위생기구 2, FCU 2, VAV 1, 구역 분전반 1, 트레이 1, 급수밸브 1 | 실당 고정(현행 좌표 규칙을 실 폭 기준 비율로) | 현행과 동일 |

`low` 는 격자 대신 현행 고정 좌표 목록(실당 조명 4·스프링클러 6·디퓨저 4·감지기 4)을 실 폭 비율로 배치.

기존 데모 상태(2F-B 연기감지기 ALARM, 3F-A FAULT)는 `det_status` 키를 `("2F","회의1",0)`, `("3F","사무A","last")` 로 옮겨 유지. 에스컬레이터 컨테이너는 `1F-A` → `1F-로비`, 덤웨이터 개구부는 2F·3F 그대로.

## 4. 부속동

### 배치

IfcSite 아래 별도 IfcBuilding. 본동과 같은 좌표계.

| 동 | 위치 | 층 | 층 이름 |
|---|---|---|---|
| 주차타워 `P` | x 44~64, y 0~16 (본동 동쪽 8 m 이격) | 지상 3층, 층고 3.0 | `P1F`, `P2F`, `P3F` |
| 후생동 `W` | x 0~20, y 26~38 (본동 북쪽, 옥외 램프 y 16.5~20.5 회피) | 지상 2층, 층고 3.5 | `W1F`, `W2F` |

층 이름에 동 접두어를 붙여 본동과 충돌을 피한다(스키마·화면 변경 없음). 모니터링 "층 × 분야" 격자에 열로 나타난다.

### 내용

- 주차타워: 층별 슬래브·외벽·경사 램프(`ramp`)·주차면 센서(격자, 2.5×5 m)·조명·열감지기·스프링클러 주관+헤드·제트팬·분전반 `LP-P{n}F`·비상분전반·중계기 `RPT-P{n}F`·IDF.
- 후생동: `W1F` 식당(주방 배기팬·가스 긴급차단밸브·가스 배관)·`W2F` 체력단련실. 말단 세트는 **축소판**: 조명·비상조명·콘센트·감지기·스프링클러·소화전·위생기구·디퓨저 없이 실내기(IfcUnitaryEquipment SPLITSYSTEM). VAV·FCU·디퓨저·급탕은 만들지 않는다(냉난방수·공조 계통을 동 밖으로 끌지 않음).
- 후생동 자체 공급원(`ctx`): 분전반 `LP-W1F`(전기), 비상분전반(비상전원), 중계기 `RPT-W`(화재감지), 알람밸브 `AV-W`(소방), 급수밸브(급수), 배수 횡주관(배수) → 지중 배수관 → 본동 집수정 SP, 옥상 EHP 실외기 `ODU-W` → 실내기(공조, 실외기는 LP-W1F 전기), IDF-W(통신). 위생기구는 급수·배수만 연결.

### 동 간 계통(정전·추적 시나리오가 동을 넘도록)

| 계통 | 경로 |
|---|---|
| 전기 | 본동 MDB → `지중 케이블 (본동→P동)` IfcCableCarrierSegment(z −1.0, 매설) → 부속동 1F 분전반 → 층 분전반 |
| 비상전원 | EMDB → 지중 비상 케이블 → 부속동 비상분전반 → 비상조명·중계기 |
| 급수 | 본동 급수 입상관 → 지중 배관 IfcPipeSegment → 부속동 급수밸브 → 실 말단 |
| 소방 | 본동 소화 입상관 → 지중 소화배관 → 부속동 알람밸브 → 주관 → 헤드 |
| 화재감지 | 부속동 감지기 → 부속동 중계기 → 본동 FACP (현행과 같은 방향: FACP 가 하류) |
| 배수 | 후생동 배수 횡주관 → 지중 배수관 → 본동 집수정 SP |
| 통신 | 본동 MDF → 지중 광케이블 → 부속동 IDF |
| 주차관제 | 본동 PCS → 주차타워 주차면 센서·입구 차단기 |
| 가스 | 본동 가스 정압기 → 후생동 주방 긴급차단밸브 |

## 5. 코드 구조

파일 하나 유지(`samples/gen/gen_mep.py`, 364 → 약 500행). 순서:

1. 상수·argparse
2. 헬퍼(`style/rep/box/pipe/cyl/ramp/void/make/system/link/chain` 현행 유지) + `grid(x, y, w, d, pitch, offset)` 추가
3. `floor_spec()` → `FLOORS`(이름, z, h, 유형)
4. 본동 구조(슬래브·벽·샤프트·계단·램프·공간) — 층고 `h` 만 층별로 바뀜, 지하 좌표 불변
5. 지하 설비·기계실·옥탑·입상(현행 코드 그대로, `H`→`h`, `top` 계산만 변경)
6. `fit_zone()` + 지상층 루프(PLAN 기반)
7. `annex_parking(origin)`, `annex_welfare(origin)` — `--annex` 에 따라 호출
8. 자기 검사 + 쓰기 + 카운트 출력

자기 검사(AssertionError):
- 계통에 배정된 모든 요소는 IfcRelConnectsElements 가 1개 이상.
- 개구부(IfcOpeningElement)를 제외한 모든 IfcElement 는 IfcSpace 또는 IfcBuildingStorey 에 직접 소속(개구부는 호스트를 통해 간접 소속).
- 생성된 IfcSpace·IfcBuildingStorey 이름은 유일.

카운트 출력은 두 줄: 원시 IFC(IfcElement 전체·IfcOpeningElement·IfcDistributionSystem)와 DB 적재 기준(개구부 제외 요소·IfcSystem 포함 계통·연결). 검증은 후자와 DB 를 비교한다.

지하 2층·B1 의 XY 배치와 Z(표고·층고)는 손대지 않는다(실 추가 시 B2 북측 방 y 4~16·남측 램프 스트립 y 0~3.8, x 5~30 회피 규칙 유지).

## 6. 산출물·검증

- IFC 는 커밋하지 않는다(`.gitignore` 의 `samples/*.ifc` 유지 — 지금도 mep-building.ifc 는 미추적). samples/README 에 기본·대형 생성 명령을 적는다.
- 워커 컨테이너에서 기본(`annex=1`)·`annex=0`·`annex=2`·대형 인자로 생성, 기본과 대형을 업로드해 확인:
  - 변환 READY, DB 적재 기준 카운트(요소·연결·계통)와 DB 값 일치
  - 층 목록에 `P1F`(기본), `W1F`(`annex=2`) 포함
  - 모니터링 층 × 분야 격자에 부속동 층 열 표시, 층 단면 링크가 본동 1F 와 `P1F` 를 각각 올바른 높이로 자름
  - 계통 추적: MDB 에서 `dir=down` 하류에 부속동 분전반 포함, 부속동 감지기에서 `dir=down` 으로 FACP 도달
  - 정전(`POST /power?source=GENERATOR`) 시 부속동 일반 조명 무전원·비상조명 유지, `UTILITY` 복전 시 복구
  - `POST /assets/bulk`, `bms_sim.py --seed 1 --ticks 5` 정상 동작
  - 대형 인자: 생성 시간·변환 시간·IFC/GLB 크기·뷰어 초기 로드 시간(헤드리스, 병합 렌더 켜짐/꺼짐)과 측정 환경 기록(② 기준선)
- 요소 수 목표(약 3천·1만 5천)는 개구부 제외 기준의 추정치이며 생성 후 실측으로 확정한다.
- README "가상 건물" 절과 samples/README 의 숫자·명령 갱신. `docs/screen-design.md` 는 층 단면 링크 설명 한 줄만 갱신.

## 7. 화면 변경 한 곳: 층 단면 링크

현재 `MonitorPage.storeyClip` 은 모든 층을 표고순으로 늘어놓고 "바로 위 항목의 표고"를 단면 상한으로 쓴다. 부속동이 들어오면 본동 1F(0 m)와 `P1F`(0 m)가 같은 표고라 상한이 0 이 되고, 층고가 다른 동의 층이 사이에 끼면 엉뚱한 높이로 자른다.

수정: 모니터 API 행에 `building`(층의 부모 IfcBuilding 이름, Sql 층 조인에 부모 한 단계 추가)을 실어 주고, `storeyClip` 은 **같은 동의 다음 층** 표고를 상한으로 쓴다. 같은 동에 다음 층이 없으면 `z0 + 3.5`(현행 최상층 처리). XY 절단 범위는 현행대로 전체(다른 동이 함께 보이는 것은 허용 — 단면은 높이 확인 용도).
층 × 분야 격자의 층 라벨은 이름에 동 접두어가 있어 그대로 둔다.
